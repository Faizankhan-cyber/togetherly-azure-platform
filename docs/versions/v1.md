## Actual deployed architecture

V1 currently runs the Togetherly Workforce frontend and TinyFish API on one Azure Linux VM. It does **not** use Azure Functions. The initial Functions-based design was not deployed; the working implementation uses a small Node.js Express service managed by systemd.

```text
                                      |

                                      |

```

## Implementation notes

- The Togetherly Workforce frontend source remains in its separate repository. Only its production build is deployed on the VM.
- The TinyFish API is a separate Node.js Express service. It is not the original Vercel deployment and it is not an Azure Functions app.
- Nginx serves the frontend and proxies `/api/tinyfish/*` to `http://127.0.0.1:3001`.
- The API process binds to loopback only. Do not expose port 3001 publicly.
- The API uses server-side environment values for Supabase and TinyFish. The API `.env` file is permission-restricted and excluded by `.gitignore`. Never commit it.
- Supabase remains an external managed service. No production database, policy, or authentication changes were made as part of this deployment.
- The Azure Functions plan, Function App, and Functions storage account were not provisioned. Azure Functions remains a possible future migration, not a V1 deliverable.
- HTTPS was tested on the public hostname; HTTP returned a redirect to HTTPS.
- The live application was opened successfully and the user confirmed TinyFish search, fetch, and agent workflows worked in the application.
