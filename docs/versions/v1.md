# V1 — Repeatable, Governed Deployment

**Status:** Planning  
**Learning alignment:** AZ-900  
**Target:** Deploy a pinned Togetherly Workforce release to Azure using repeatable Azure CLI scripts.

## Scope

- Repository and script conventions.
- Resource group, VNet, subnet, NSG, public IP/DNS label, and eligible small B-series VM (subject to subscription availability).
- Required resource tags and budget notifications.
- Private, TLS-only storage account for documented build artifacts/backups.
- Ubuntu cloud-init, Nginx, Node.js runtime, non-root service user, and systemd service.
- GitHub Actions build and deployment of a pinned Togetherly revision.
- HTTPS using Let's Encrypt on the Azure DNS name.
- Smoke tests, architecture documentation, cost review, and teardown verification.

## Acceptance criteria

- [ ] Pinned application build is deployed and loads over HTTPS.
- [ ] Supabase login and required application flows work.
- [ ] TinyFish API routes work through the documented Node.js/Nginx integration.
- [ ] SSH is restricted to the administrator's current IP; only required web ports are public.
- [ ] Resources carry project, version, owner, and environment tags.
- [ ] Storage access is private and TLS-only.
- [ ] GitHub Actions build/deploy workflow succeeds.
- [ ] Smoke tests pass before and after a full rebuild.
- [ ] Scripts can create, verify, and tear down the V1 environment.
- [ ] Evidence and cost records are committed before teardown.

## Evidence checklist

- [ ] Sanitised deployment logs and relevant Azure CLI output.
- [ ] Resource inventory showing required tags.
- [ ] Budget configuration and cost view.
- [ ] Azure Advisor review and documented findings.
- [ ] Storage configuration and access settings.
- [ ] HTTPS response and browser screenshot.
- [ ] Successful GitHub Actions run.
- [ ] Smoke-test output before and after rebuild.
- [ ] Architecture diagram and known-gaps record.
- [ ] Teardown and post-cleanup verification.

## Known risks and gaps

- The existing Togetherly TinyFish handlers may require a small Node.js compatibility wrapper. Inspect source before choosing a process model.
- V1 temporarily uses a restricted environment file for the TinyFish credential. V2 must replace this with Managed Identity and Key Vault; do not commit the file or credential.
- Azure region, VM-size availability, DNS label availability, pricing, and subscription restrictions must be checked before deployment.

## Cost target

Planning target: approximately **US$15** from the initial credit envelope. This is not a quote or spending cap. Validate pricing before deployment and review actual cost data.
